# Media3 1.9 -> 1.11 upgrade audit

This audit covers the complete jump from the app's previous Media3 1.9.2
dependencies through Media3 1.10.x and 1.11.0. Items are classified as:

- DONE: implemented in this worktree.
- AUTOMATIC: provided by the Media3 upgrade; no app code is required.
- ADD: a worthwhile app capability or targeted improvement that is not yet implemented.
- NOT NEEDED: technically available, but not a fit for StreamVault's current architecture.
- WATCH: useful only if future telemetry or product requirements justify it.

Primary source: https://developer.android.com/jetpack/androidx/releases/media3

## Work already completed in this worktree

These items are complete and should not remain in the pending migration list:

- DONE - Upgraded all Maven Media3 dependencies from 1.9.2 to 1.11.0.
- DONE - Replaced the bundled FFmpeg decoder AAR with the matching Media3 1.11.0 artifact, including checksum and ABI/decoder verification.
- DONE - Replaced the legacy `SingleSampleMediaSource` external-subtitle path with `MediaItem.SubtitleConfiguration` plus extraction-based subtitle loading. Optional subtitle I/O failures remain non-fatal to video playback.
- DONE - Migrated the custom PCM tap to `AudioSink.AudioSinkConfig`, preserving audio format, timeline/period context, and tap behavior.
- DONE - Migrated the custom video renderer construction to `MediaCodecVideoRenderer.Builder`, preserving the decoder-reuse workaround.
- DONE - Migrated `setViewportSizeToPhysicalDisplaySize` to the current API.
- DONE - Enabled `DefaultExtractorsFactory.setDisableArtworkMetadata(true)` for playback extractors to reduce unnecessary cover-art memory use on TV devices.
- DONE - Added regression/unit coverage for external subtitles, audio-sink configuration, decoder reuse, and the FFmpeg artifact.

## Media3 1.10.x findings

### Automatic benefits already received by upgrading to 1.11.0

- AUTOMATIC - `ProgressiveMediaSource` timeline propagation fix. The app uses progressive sources for VOD and side-loaded subtitles, so the fix is inherited without an app change.
- AUTOMATIC - Decoder-error recovery/prewarming fixes, AV1 Dolby Vision initialization fixes, codec-reuse improvements, RTSP packet parsing fixes, HLS fallback/`EXT-X-MAP` fixes, DASH seek/timeline fixes, and audio-output retry improvements.
- AUTOMATIC - Dynamic video scheduling introduced in 1.10 and enabled by default at the ExoPlayer level in 1.11. No explicit opt-in is required for the current player.
- AUTOMATIC - VobSub cue-duration handling and 1.11 TTML parser fixes. These improve subtitle timing/availability but are not a guaranteed fix for the reported subtitle-freeze issue.
- AUTOMATIC - HLS redundant-location fallback, HLS `QUERYPARAM`/`X-PLAYOUT-LIMIT` handling, HLS ID3 metadata-track exposure, and DASH CEA caption grouping/location fallback.
- AUTOMATIC - Dolby Vision Profile 10, VVC container parsing, larger MP4 `uuid` boxes, and other extractor/codec compatibility fixes where the device decoder supports the format.
- AUTOMATIC - Media3 1.10's stable track-selection preferences and Media3 1.11's continued track-selection fixes are available to the existing `PlayerTrackController`.

### Existing app functions worth evaluating against 1.10 APIs

- DONE - Preferred subtitle-language selection. Media3 text-selection parameters now use the saved VOD subtitle language as the automatic fallback (`preferredTextLanguage` plus `selectTextByDefault`), while the app-owned persisted track ID/label resolver remains authoritative when it can match a track and explicit disabled choices remain disabled.
- ADD - Media3 `FrameExtractor` pilot for VOD seek thumbnails. Media3 1.10 moved this API to the `media3-inspector-frame` module. The current `SeekThumbnailProvider` uses Android `MediaMetadataRetriever`, can block on remote URLs, and excludes HLS/DASH. Pilot implementation is now behind the existing provider interface: Media3 is first for supported non-live, non-DRM VOD, with the current provider retained as a fallback. Player/feature tests, the dependency boundary, app Hilt wiring, and a debug APK build pass. Emulator smoke playback remains healthy, but the controlled device/content latency matrix is still pending; do not remove the legacy implementation yet.
- WATCH - `DefaultPreloadManager.Builder.setDataSourceFactory`. This is useful only if the app adopts Media3's preload manager; it allows the app's custom headers, timeouts, and proxy behavior to be reused by preloading.

### 1.10 APIs that should not replace current code

- NOT NEEDED - `Player.mute()`/`unmute()`. They became stable in 1.10, but the app's `PlayerAudioFocusController` preserves volume, coordinates focus/ducking, and exposes state; replacing it would lose behavior.
- NOT NEEDED - Media3 Compose `Player`, `ProgressSlider`, and playback-speed composables. StreamVault has custom TV/DPAD controls, overlays, subtitle styling, surfaces, and a `PlayerEngine` boundary that intentionally hides Media3 from `:feature:playback`.
- NOT NEEDED - `RemoteCastPlayer.Builder.setTrackSelector`. StreamVault uses the Google Cast SDK directly through `CastManager`, not Media3 `CastPlayer`.
- NOT NEEDED - Transformer, IMA, IAMF, Lottie-effect, widget, download, and muxer additions. The app does not currently use those Media3 product areas.

## Media3 1.11.0 findings

### Automatic benefits already received

- AUTOMATIC - ExoPlayer concurrency, codec operating-rate, codec-flush, audio-session, scrubbing, and dynamic-scheduling fixes.
- AUTOMATIC - `DefaultLoadControl` low-memory protection, audio-renderer underrun grace period, fixed PCM buffer sizing, explicit decoder channel-mask handling, and MPEG-TS DTS-HD/DTS Express extraction fixes.
- AUTOMATIC - TTML region/style cue fixes, improved MP4/Matroska chapter parsing, fragmented-MP4 `mfra` seeking, Matroska ALAC/color/chapter handling, and MPEG-TS last-frame handling.
- AUTOMATIC - HLS Content Steering/Pathway Cloning support and HLS `SCORE` parsing into `Format.selectionPriority`. No app code is required for manifests that provide these features.
- AUTOMATIC - Safer default `MediaSession` controller access and the 1.11 session-threading/deadlock fixes. The app creates a basic `MediaSession` without a custom callback, so there is no `onConnect` migration to perform.
- AUTOMATIC - `Format.channelMask` and the corresponding audio-channel configuration logic. The custom audio sink now receives the richer `AudioSinkConfig`.

### Worth adding as new capabilities or targeted improvements

- DONE (P1) - VOD chapter navigation. Media3 `Chapter` metadata is normalized into the player boundary, exposed as chapter state, and surfaced in the new video-first VOD overlay with timeline markers, chapter sheet selection, and previous/next chapter actions. Live and catch-up overlays remain on their existing path; chapter actions are hidden while Cast is connected.
- DONE - Adaptive startup bitrate. `DefaultBandwidthMeter.InitialBitrateSupplier` now uses Media3's network-class defaults when no history exists, or a discounted/capped estimate from the previous provider measurement when the player is recreated. The bandwidth meter is wired into the existing foreground data-source transfer listener and resets on network changes; user quality settings are unchanged.
- ADD (P2) - VOD/episode sliding-window preloading — IMPLEMENTED PILOT. `DefaultPreloadManager` with `SimpleRankingDataComparator` now manages a maximum of three current/adjacent series-episode or catch-up candidates. Candidates use the app's preload-scoped data source path, preserve resolved provider metadata, skip live/DRM/expired/unsupported entries, and fall back to direct playback on a miss. The feature layer refreshes after `READY` and asynchronous episode/channel context resolution, fingerprints unchanged windows, guards stale sessions, and keeps the existing legacy single-item path for ordinary live zapping and recovery. Player/feature/app unit tests, the feature boundary check, and a debug APK build pass. The real-device/content latency, request-shape, lifecycle, and foreground-transfer-accounting matrix is still pending; do not remove the legacy path until that gate passes.
- WATCH (P2) - Custom adaptive variant ordering. Media3 now exposes `Format.selectionPriority` and `AdaptiveTrackSelection.Factory.setTrackFormatComparator`. The default HLS `SCORE` mapping is already automatic; add a custom comparator only after telemetry shows provider scores or user quality preferences need different ordering.
- WATCH (P3) - Explicit per-stream media progression. `ExoPlayer.Builder.enablePerStreamMediaProgression()` can reduce transitions between queued short items, but the app normally replaces one media source at a time rather than playing a Media3 playlist. Do not enable it globally yet.

### 1.11 capabilities not suitable for the current app

- NOT NEEDED - Media3 Compose `PlayerDefaults`, control slots, `MiniController`, `PlayerPool`, and Compose state holders. These would duplicate StreamVault's custom player UI and lifecycle rather than extend it.
- NOT NEEDED - `media3-datasource-ktor`. The player depends on custom OkHttp headers, TLS policy, proxy behavior, timeouts, and transfer accounting; switching stacks provides no feature benefit.
- NOT NEEDED - `CastParams`/SystemUI Output Switcher migration for now. It would require moving or bridging the existing Google Cast implementation to Media3 Cast and would create a large parallel playback path.
- NOT NEEDED - HAGC/Eclipsa timed HDR metadata. It targets progressive media on API 37+ devices and has no current product requirement; the project currently compiles against API 36.
- NOT NEEDED - Ogg/WAV muxers, track-reference muxing, Transformer, IMA, and other authoring APIs. StreamVault is a playback application.

## Subtitle-freeze relevance

The upgrade includes automatic subtitle-parser improvements from both 1.10 and 1.11, and the external subtitle path is DONE above. There is still no Media3 1.10/1.11 switch that guarantees recovery from a frozen embedded subtitle track. Embedded-subtitle behavior remains unverified on the affected device/content and should be instrumented separately if the report persists.

## Remaining implementation backlog

1. Design and test VOD-only sliding-window preloading before replacing the current single-source preload path.
2. Keep custom variant ordering and Media3 Cast migration as telemetry-driven follow-ups, not automatic parts of the 1.11 upgrade.
